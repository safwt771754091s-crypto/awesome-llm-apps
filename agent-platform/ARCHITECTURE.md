# منصة الوكلاء المستقلة لبناء التطبيقات والمنصات

## الهدف
تحويل مركز الوكلاء إلى مساحة عمل يكتب فيها المالك طلباً باللغة العربية، ثم تتحول النية إلى مشروع قابل للفحص: خطة، مواصفات، ملفات، اختبارات، ومعاينة. لا يجوز إظهار المهمة على أنها نُفذت أو نُشرت إلا بعد تحقق آلي من النتيجة.

## الفرق عن النسخة الحالية
النسخة الحالية واجهة ثابتة وخط أنابيب نصي من أربع استدعاءات نموذج. ليست مشغّل شيفرات، ولا تنشئ مستودعاً كاملاً بصورة آمنة، ولا تحول الكتب إلى تطبيقات فعلياً. هذا الملف يحدد البنية اللازمة للانتقال إلى منتج تنفيذي.

## البنية المقترحة
- **واجهة الويب وPWA:** واجهة RTL عربية، مساحة مشروع، محادثة مهام، مراحل التنفيذ، معاينة وملفات ومخرجات.
- **خادم API موثوق:** مصادقة مالك ومستخدمين، صلاحيات RBAC، حدود استخدام، إدارة مهام، سجل تدقيق، وعدم إرسال مفاتيح النموذج إلى المتصفح.
- **منسّق الوكلاء:** مدير مهام يجزئ الطلب ويعيّن أدواراً متخصصة (محلل متطلبات، معماري، واجهة، Backend/DB، اختبارات وأمن، نشر). تُحفظ الحالة ويمكن استئناف المهام المتوقفة.
- **بيئة تنفيذ معزولة:** تشغيل الشيفرة والاختبارات في sandbox منفصل محدود CPU/RAM/وقت/شبكة، لا على خادم API، ولا بصلاحيات المستودع أو أسرار الإنتاج.
- **ملفات ومشاريع:** مساحة عمل لكل مشروع، نسخ/إصدارات، Git branches وcommits، artifacts وسجل بناء.
- **قاعدة بيانات مستقلة:** تخزين المستخدمين والمشاريع والمهام والمراحل والسجلات. لا يعاد استخدام قواعد بيانات مشاريع أخرى دون موافقة صريحة.
- **مزود النماذج:** موصل متوافق مع OpenAI API من جهة الخادم مع أسرار في متغيرات البيئة، ميزانيات وحدود طلبات.
- **رفع الكتب:** رفع PDF وصور، OCR عند الحاجة، استخراج النص والفصول والجداول والصور، معاينة ومراجعة جودة، ثم تحويل المحتوى إلى قارئ أو دروس أو اختبارات أو تطبيق تعليمي.
- **النشر:** معاينة مؤقتة أولاً، ثم نشر الويب أو إعداد APK عند طلب المستخدم. يلزم تأكيد قبل إنشاء موارد مدفوعة أو حذف بيانات أو نشر عام.

## مسار المهمة
1. يستقبل النظام الطلب والملفات ويحدد نوع المخرج: تطبيق، منصة، متجر، تحويل كتاب، أو تعديل مشروع.
2. يسأل سؤالاً واحداً فقط إذا كان هناك قرار حاسم لا يمكن استنتاجه؛ وإلا يستخدم إعدادات افتراضية موثقة.
3. ينشئ مواصفات قابلة للمراجعة وخطة مهام ومعايير قبول.
4. ينفذ الوكلاء في فروع/مساحات منفصلة ويجمعون الملفات.
5. يشغل الاختبارات الثابتة واختبارات الوظائف وفحوصات الأسرار والتبعيات.
6. يعرض المعاينة والتغييرات والأخطاء، ويصلحها ضمن عدد محاولات مضبوط.
7. ينشر فقط بعد اجتياز الفحوصات والموافقة المطلوبة، ثم يتحقق من الرابط النهائي.
8. يعرض تقرير تسليم: ما اكتمل، ما فشل، الروابط، التكاليف التقديرية، والقيود المتبقية.

## مراحل التنفيذ
### المرحلة 1 — منصة التنفيذ الأساسية
- Backend آمن ومصادقة حقيقية وصلاحيات مالك من جهة الخادم.
- مهام دائمة وحالة مراحل وإلغاء/استئناف وسجل تدقيق.
- مدير وكلاء وموصل نموذج على الخادم.
- تكامل GitHub لإنشاء فرع وملفات وPull Request، دون كشف مفاتيح الوصول.
- اختبار end-to-end لمهمة بسيطة تنشئ تطبيق ويب صغيراً وتتحقق من البناء.

### المرحلة 2 — منشئ التطبيقات والمنصات
- قوالب React/Next.js أو تطبيق ويب ثابت حسب طبيعة الطلب.
- توليد مخطط بيانات وواجهات API واختبارات.
- معاينة sandbox آمنة، وإصلاح أخطاء البناء، وتصدير المشروع أو فتح PR.
- لا تُنشأ خدمات أو قواعد بيانات مدفوعة تلقائياً.

### المرحلة 3 — تحويل الكتب إلى تطبيقات
- رفع PDF/صور، OCR عند الضرورة، استخراج منظم مع الإشارة إلى الصفحات الأصلية.
- أدوات مراجعة للنصوص والصور قبل الاعتماد.
- مخرجات: قارئ كتاب، دروس، بطاقات تعليمية، اختبارات، بحث داخل الكتاب.
- حماية حقوق المحتوى؛ يرفع المستخدم المواد التي يملك حق استخدامها.

### المرحلة 4 — النشر وAndroid
- ربط مزود استضافة وخط CI/CD.
- فحص النتيجة المنشورة فعلياً قبل عرض رابط النجاح.
- بناء APK قابل للتثبيت؛ توقيع إصدار Android يتطلب إعداد keystore آمن من المالك ولا يضمّن في المستودع.
- مراقبة الاستخدام والتكلفة وإمكانية إيقاف/حذف المشاريع.

## معايير الأمان والقبول
- لا توجد أسرار API في JavaScript أو localStorage أو ملفات Git.
- المصادقة والصلاحيات على الخادم، لا في الواجهة فقط.
- لا تشغيل لشيفرة مولدة في بيئة الخادم الرئيسية.
- تقييد الشبكة والملفات والموارد داخل sandbox، مع مهلة وحد أقصى للتكلفة.
- موافقة صريحة على النشر العام، المدفوعات، الحذف، وإرسال المحتوى إلى مزود خارجي.
- اختبارات آلية وفحص أسرار وتبعيات قبل الدمج.
- لا يُعلن نجاح البناء أو النشر إلا بناءً على نتيجة فعلية ورابط تم التحقق منه.

## متطلبات التشغيل التي لا يمكن تجاوزها
هذه المنصة تحتاج خدمة Backend عاملة، مزود نماذج وإعدادات أسرار، sandbox لتشغيل المشاريع، تخزيناً للمهام والملفات، وصلاحيات GitHub/الاستضافة. GitHub Pages وحده يستضيف ملفات ثابتة ولا يشغّل هذه البنية الخلفية. يمكن أن تكون الواجهة العامة على Pages، لكن التنفيذ يحتاج خدمة خلفية منفصلة.

## الحالة
هذه الوثيقة معمارية تنفيذ وليست ادعاءً بأن الميزات المذكورة قد بُنيت أو نُشرت. يجب تنفيذ كل مرحلة واختبارها على حدة، مع الحفاظ على مركز الوكلاء الحالي وعدم خلطه بمشاريع المستخدم الأخرى.
